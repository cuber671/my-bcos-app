### 1. 信用管理模块核心逻辑

信用模块不是静态的标签，而是一个 **动态积分系统** 。它通过采集仓单、物流、金融三个模块的底层行为，自动计算信用分。

* **信用加分（合规奖励）** ：准时还款、货物无损达、入库量巨大且稳定。
* **信用扣分（违约惩罚）** ：逾期还款（按天扣）、物流路径严重偏移、仓单数据异常、频繁撤单。
* **等级应用（差异化服务）** ：
* **高信用（AAA）** ：可以获得更高的 **质押率** （比如货值 100 万能借 90 万），更低的物流监控频率。
* **低信用（C/D）** ：降低质押率（只能借 50 万），系统强制要求司机必须开启摄像头监控提货过程。

### 2. 信用档案表 (`Enterprise_Credit_Profile`)

该表记录企业的实时信用状态。

| **字段名**              | **类型** | **约束**   | **说明**                                                |
| ----------------------------- | -------------- | ---------------- | ------------------------------------------------------------- |
| **`id`**              | `Long`       | 主键             | 信用记录唯一 ID。                                             |
| **`ent_id`**          | `Long`       | `Unique`       | 关联企业 ID。                                                 |
| **`credit_score`**    | `Integer`    | `Default: 800` | **信用评分** ：初始分 800，范围 300-1000。              |
| **`credit_level`**    | `String`     | `NotNull`      | **信用等级** ：AAA, AA, A, B, C, D。                    |
| **`available_limit`** | `Decimal`    | `NotNull`      | **授信额度** ：平台允许该企业同时存在的未结清账款总额。 |
| **`used_limit`**      | `Decimal`    | `Default: 0`   | **已用额度** ：当前未结清的应收款总和。                 |
| **`overdue_count`**   | `Integer`    | `Default: 0`   | **逾期次数** ：累计历史违约次数。                       |
| **`last_eval_time`**  | `DateTime`   | `NotNull`      | **上次评估时间** ：系统自动跑分的日期。                 |

### 3. 信用评估 API 接口设计

| **接口名称**     | **路径 (Method)**           | **后台逻辑说明 (通俗易懂版)**                                                       |
| ---------------------- | --------------------------------- | ----------------------------------------------------------------------------------------- |
| **获取信用画像** | `/credit/profile/{ent_id}`(GET) | **看一眼准不准** ：查看企业的信用分、等级、授信额度使用情况。                       |
| **违约事件上报** | `/credit/event/report`(POST)    | **打小报告** ：金融模块发现逾期，或风控发现偏航时，自动触发。系统根据事件等级扣分。 |
| **信用等级重算** | `/credit/reevaluate`(PATCH)     | **定期体检** ：系统每月根据企业的交易频次、履约率自动更新分数和等级。               |
| **额度实时锁死** | `/credit/limit/lock`(POST)      | **防爆雷** ：当企业已用额度超过授信总额时，自动拦截物流委派单的生成。               |

### 4. 信用模块与其它模块的联动矩阵 (ABAC 增强)

信用模块的作用不仅是看，而是直接干预业务流程：

| **联动模块** | **高信用企业 (AAA/AA)**                            | **低信用企业 (C/D)**                                   |
| ------------------ | -------------------------------------------------------- | ------------------------------------------------------------ |
| **仓单模块** | 允许自助进行仓单拆分。                                   | 仓单拆分必须经过平台人工介入审核。                           |
| **物流模块** | 司机只需扫码，无需强制上传现场照片。                     | 必须上传“装车照片 + 车牌合影”，开启 GPS 实时监控。         |
| **金融模块** | 质押率可达**90%** ；支持先放货后清账（信用提货）。 | 质押率最高**50%** ；必须现金结清才允许生成物流委派单。 |

---

### 5. 信用预警：信用黑名单

如果企业的信用分跌破阈值（如 < 400 分），信用模块会向**风控模块**发出指令，触发“熔断机制”：

1. **全局禁言** ：禁止在平台上发布任何求购或转让单。
2. **资产锁定** ：锁定名下所有仓单。
3. **银行预警** ：自动向关联的融资银行发送风险提示函。

---

### 💡 通俗解释这个模块：

这个模块就是平台的“红黑榜”。

* **AAA 企业**是“特权阶层”，手续简便，额度高。
* **D 级企业**是“重点监控对象”，干什么都要审批，且只能借很少的钱。
* **系统自动打分** ：不用人工干预，还款准时分就涨，逾期违约分就掉，公正透明。
