# 智能合约模块架构设计

## 1. 合约目录结构

```
contracts/
├── lib/                           # 基础库（通用工具）
│   ├── LibBytes.sol              # 字节操作工具
│   ├── LibString.sol             # 字符串操作工具
│   └── LibAddress.sol            # 地址操作工具
│
├── enterprise/                    # 企业管理模块
│   ├── EnterpriseRegistryCore.sol # 企业注册核心
│   └── EnterpriseRegistryAuth.sol # 企业权限控制
│
├── warehouse/                     # 仓单模块
│   ├── WarehouseReceiptCore.sol   # 仓单核心（创建、转移、锁定）
│   ├── WarehouseReceiptOps.sol    # 仓单操作（拆分、合并、背书）
│   └── WarehouseReceiptHistory.sol # 仓单历史记录
│
├── receivable/                    # 应收款模块
│   ├── ReceivableCore.sol        # 应收款核心（创建、确认、调整）
│   └── ReceivableRepayment.sol   # 还款管理
│
└── credit/                       # 信用管理模块
    ├── CreditLimitCore.sol       # 信用额度核心
    └── CreditLimitScore.sol      # 信用评分
```

## 2. 模块拆分方案

### 2.1 EnterpriseRegistry 模块

**拆分原因**：
- 核心业务逻辑与权限控制分离，便于维护
- 避免单个合约函数过多导致栈溢出

**拆分方案**：

| 合约 | 职责 | 主要方法 |
|------|------|----------|
| EnterpriseRegistryCore | 企业信息管理 | registerEnterprise, getEnterpriseInfo, isEnterpriseValid |
| EnterpriseRegistryAuth | 权限控制 | onlyAdmin, onlyJavaBackend, onlyEnterpriseOwner |

### 2.2 WarehouseReceipt 模块

**拆分原因**：
- 核心操作与高级操作（拆分合并）分离
- 历史记录独立存储，减少核心合约复杂度
- 避免栈溢出

**拆分方案**：

| 合约 | 职责 | 主要方法 |
|------|------|----------|
| WarehouseReceiptCore | 仓单生命周期 | mintReceipt, burnReceipt, lockReceipt, unlockReceipt, transfer |
| WarehouseReceiptOps | 高级操作 | splitReceipt, mergeReceipts, launchEndorsement, confirmEndorsement |
| WarehouseReceiptHistory | 历史记录 | recordHistory, getHistory, getHistoryCount |

### 2.3 Receivable 模块

**拆分原因**：
- 核心业务与还款逻辑分离
- 便于独立演进

**拆分方案**：

| 合约 | 职责 | 主要方法 |
|------|------|----------|
| ReceivableCore | 应收款管理 | createReceivable, confirmReceivable, adjustReceivable |
| ReceivableRepayment | 还款管理 | recordRepayment, offsetDebtWithCollateral |

### 2.4 CreditLimit 模块

**拆分原因**：
- 额度管理与评分计算逻辑分离
- 便于算法独立优化

**拆分方案**：

| 合约 | 职责 | 主要方法 |
|------|------|----------|
| CreditLimitCore | 额度管理 | reportCreditEvent, updateLimit |
| CreditLimitScore | 信用评分 | calculateScore, checkLimit |

## 3. 数据上链字段规范

### 3.1 字段分类

| 分类 | 上链方式 | 存储位置 | 适用场景 |
|------|----------|----------|----------|
| **明文上链** | 直接存储 | 区块链 | 公开检索、业务对账、状态流转、金额计算 |
| **哈希化上链** | Hash(ID+Salt) | 区块链 | 隐私保护、身份验证 |
| **全摘要存证** | IPFS CID | 区块链 | 大文件（照片、视频、PDF） |

### 3.2 各模块字段规范

#### 企业模块 (EnterpriseRegistry)

| 字段 | 上链方式 | 理由 |
|------|----------|------|
| enterpriseAddress | 明文 | 公开检索、主键 |
| creditCode | 明文 | 公开检索、索引 |
| role | 明文 | 权限控制 |
| status | 明文 | 状态流转 |
| registeredAt | 明文 | 时间逻辑 |
| updatedAt | 明文 | 时间逻辑 |
| metadataHash | 哈希化 | 企业详细信息哈希 |

#### 仓单模块 (WarehouseReceipt)

**明文上链**：
| 字段 | 理由 |
|------|------|
| receiptId | 公开检索、唯一标识 |
| weight | 业务对账、金额计算 |
| unit | 单位标准化 |
| quantity | 数量统计 |
| status | 状态流转控制 |
| storageDate | 时间逻辑 |
| expiryDate | 时间逻辑 |
| frozen | 状态控制 |

**哈希化上链**：
| 字段 | 哈希公式 |
|------|----------|
| ownerHash | Hash(货主ID + Salt) |
| warehouseHash | Hash(仓库ID + Salt) |

**全摘要存证**：
| 字段 | 说明 |
|------|------|
| goodsDetailHash | IPFS 货物详情哈希 |
| locationPhotoHash | IPFS 现场照片哈希 |
| contractHash | IPFS 合同文件哈希 |

#### 应收款模块 (Receivable)

**明文上链**：
| 字段 | 理由 |
|------|------|
| receivableId | 唯一标识 |
| initialAmount | 金额计算基准 |
| balanceUnpaid | 实时余额 |
| dueDate | 逾期判断 |
| status | 状态流转 |

**哈希化上链**：
| 字段 | 哈希公式 |
|------|----------|
| buyerSellerPairHash | Hash(买方ID + 卖方ID + Salt) |

**全摘要存证**：
| 字段 | 说明 |
|------|------|
| invoiceHash | IPFS 发票哈希 |
| contractHash | IPFS 合同哈希 |
| goodsDetailHash | IPFS 货物详情哈希 |

#### 信用模块 (CreditLimit)

**明文上链**：
| 字段 | 理由 |
|------|------|
| creditLimit | 额度值 |
| creditScore | 评分值 |
| lastUpdateTime | 时间逻辑 |

**哈希化上链**：
| 字段 | 哈希公式 |
|------|----------|
| eventDataHash | Hash(事件详情 + Salt) |

## 4. 栈溢出防护规则

### 4.1 参数封装

```solidity
// 超过4个参数必须用 Struct
struct ReceiptInput {
    string receiptId;
    bytes32 ownerHash;
    bytes32 warehouseHash;
    uint256 weight;
    string unit;
    uint256 quantity;
    uint256 storageDate;
    uint256 expiryDate;
    bytes32 goodsDetailHash;
}
```

### 4.2 Calldata 传参

```solidity
// 数组参数必须用 calldata
function getReceipts(string[] calldata ids) external view returns (...) {}
```

### 4.3 作用域隔离

```solidity
function complexOperation(...) external {
    { uint256 a = computeA(); uint256 b = computeB(); }
    { uint256 c = computeC(); uint256 d = computeD(); }
}
```

### 4.4 批量限制

```solidity
uint256 constant MAX_BATCH_SIZE = 50;
require(receiptIds.length <= MAX_BATCH_SIZE, "Batch size too large");
```

### 4.5 分页查询

```solidity
function getReceiptsByPage(uint256 offset, uint256 limit) external view returns (...) {
    require(limit <= 100, "Limit too large");
}
```
