# FISCO BCOS 供应链金融平台 - 项目目录结构说明

## 一、项目概述

**项目名称**: my-bcos-app (FISCO BCOS 供应链金融平台)

**技术栈**: Spring Boot 2.7.18 + Java 11 + Maven + MySQL 8.0 + FISCO BCOS 3.12.1

**项目定位**: 基于区块链的供应链金融平台，支持企业注册、仓单管理、票据管理、应收款管理、信用管理等核心功能

## 四、Docker Compose 服务说明

### 4.1 服务列表

| 服务名 | 说明 | 端口映射 | 静态 IP |
|--------|------|----------|---------|
| fisco-node0 | FISCO 节点 0 | 20000, 30300 | 172.25.0.10 |
| fisco-node1 | FISCO 节点 1 | 20001, 30301 | 172.25.0.11 |
| fisco-node2 | FISCO 节点 2 | 20002, 30302 | 172.25.0.12 |
| fisco-node3 | FISCO 节点 3 | 20003, 30303 | 172.25.0.13 |
| fisco-console | FISCO 控制台 | - | DHCP |
| fisco-dev-db | MySQL 8.0 | 3306 | DHCP |
| fisco-app | Spring Boot 应用 | 8080 | DHCP |

### 4.2 网络配置

```yaml
networks:
  fisco-net:
    driver: bridge
    ipam:
      config:
        - subnet: 172.25.0.0/16    # 静态子网
```

### 4.3 节点 P2P 互联

每个节点的 `nodes.json` 配置使用 Docker 容器名进行 DNS 解析：
- node0 → fisco-node1:30001, fisco-node2:30002, fisco-node3:30003
- node1 → fisco-node0:30000, fisco-node2:30002, fisco-node3:30003
- ...

## 五、数据库管理 (Flyway)

### 5.1 配置

application.yml 中的 Flyway 配置:
```yaml
spring:
  flyway:
    enabled: true
    baseline-on-migrate: true
    locations: classpath:db/migration
```

### 5.2 迁移脚本位置

```
src/main/resources/db/migration/
├── V1__initial_schema.sql    # 初始表结构
└── V2__xxx.sql              # 后续迁移
```

### 5.3 执行时机

1. **init 脚本** (docker/mysql/init/01-init.sql): MySQL 容器首次创建时执行
   - 创建数据库 `fisco_data`
   - 创建用户 `fisco_user`
   - 设置时区

2. **Flyway 迁移**: Spring Boot 应用启动时执行
   - 创建业务表结构
   - 版本追踪

## 六、命名规范

### 6.1 目录命名

| 类型 | 规则 | 示例 |
|------|------|------|
| Java 源码 | 驼峰 (camelCase) | enterpriseModule, serviceLayer |
| 配置文件 | 短横线 (kebab-case) | application-dev.yml |
| 文档 | 中文描述 | 项目目录结构说明.md |
| 智能合约 | 帕斯卡 (PascalCase) | EnterpriseRegistryV2.sol |

### 6.2 模块划分

```
Modules/
├── Enterprise/     # 企业管理
├── User/          # 用户管理
├── Warehouse/     # 仓单管理
├── Bill/         # 票据管理
├── Finance/       # 金融模块
├── Logistics/    # 物流模块
├── Blockchain/   # 区块链交互
└── Test/         # 测试
```

### 6.3 分层架构

每个业务模块采用标准分层:
- **Controller**: REST API 入口
- **Service**: 业务逻辑
- **Mapper**: 数据访问 (MyBatis-Plus)
- **Entity**: 数据库实体
- **DTO**: 数据传输对象
- **VO**: 视图对象
- **Enums**: 业务枚举
- **Converter**: 对象转换
- **Handler**: 请求处理

## 七、验证方法

```bash
# 1. 编译项目
mvn clean compile

# 2. 启动 Docker 服务
docker compose up -d

# 3. 查看日志
docker compose logs -f

# 4. 检查节点状态
curl -X POST http://localhost:20000 -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"getConsensusStatus","params":[],"id":1}'

# 5. 访问应用
```
