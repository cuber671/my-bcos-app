## 二、各模块上链详情

### 模块一：企业管理模块

#### 1.1 企业注册

| 项目                   | 内容                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **业务场景**     | 企业在平台注册，系统生成雪花ID，调用SDK生成区块链地址与私钥                                                                                                                                |
| **对应接口**     | `POST /ent/register`（来源：企业管理模块.md 第2节）                                                                                                                                      |
| **上链等级**     | ✅**必须上链**                                                                                                                                                                       |
| **上链原因**     | 企业区块链身份是整个供应链金融体系的信任根基；区块链地址与企业法定身份一一对应，是资产确权的先决条件；私钥生成涉及资产控制权，必须上链存证                                                 |
| **上链内容**     | `ent_id`（企业ID）、`enterprise_name`（企业名称）、`org_code`（统一社会信用代码）、`blockchain_address`（区块链公开地址）、`ent_role`（业务角色）、`create_time`（注册时间戳） |
| **上链时机**     | 企业注册接口执行成功后，立即上链                                                                                                                                                           |
| **链上逻辑**     | 存证：企业身份信息上链存证；事件：抛出 `EnterpriseRegistered` 事件                                                                                                                       |
| **建议合约方法** | `function registerEnterprise(uint256 entId, string memory enterpriseName, string memory orgCode, uint8 entRole) external returns (address enterpriseAddress);`                           |
| **风险/建议**    | ⚠️ 私钥生成必须在安全环境（AES加密存储），严禁明文落库；⚠️ 需考虑企业重名场景，建议在链上校验 `org_code` 唯一性                                                                      |

#### 1.2 发起注销 - 链上资产余额校验

| 项目                   | 内容                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------- |
| **业务场景**     | 企业申请注销时，校验链上资产余额是否清零                                               |
| **对应接口**     | `POST /ent/cancellation/apply`（来源：企业管理模块.md 第2节）                        |
| **上链等级**     | ✅**必须上链**                                                                   |
| **上链原因**     | 涉及资产清算，必须确保链上资产已全部处置；防止企业带资产注销后产生纠纷                 |
| **上链内容**     | `ent_id`、`blockchain_address`、`asset_balance`、`cancellation_time`           |
| **上链时机**     | 注销申请发起时，调用链上接口查询资产余额                                               |
| **链上逻辑**     | 查询：调用合约 `getAssetBalance(entId)`；校验：余额必须为0才允许注销                 |
| **建议合约方法** | `function getEnterpriseAssetBalance(uint256 entId) external view returns (uint256);` |
| **风险/建议**    | ⚠️ 需同时校验仓单、应收款等各类链上资产；⚠️ 需考虑质押中资产的处理逻辑             |

#### 1.3 获取企业详情 - 区块链地址展示

| 项目                   | 内容                                                                                                                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 返回企业基础资料、角色、状态及区块链公开地址                                                                                                                                             |
| **对应接口**     | `GET /ent/info_detail`（来源：企业管理模块.md 第2节）                                                                                                                                  |
| **上链等级**     | 🔔**建议上链**                                                                                                                                                                     |
| **上链原因**     | 区块链地址是企业链上身份的重要标识；便于交易对手方核验企业真实性                                                                                                                         |
| **上链内容**     | `blockchain_address`                                                                                                                                                                   |
| **上链时机**     | 查询详情时返回                                                                                                                                                                           |
| **链上逻辑**     | 从链上查询企业注册信息进行交叉验证                                                                                                                                                       |
| **建议合约方法** | `function getEnterpriseInfo(uint256 entId) external view returns (string memory enterpriseName, string memory orgCode, address blockchainAddress, uint8 entRole, uint256 createTime);` |

### 模块三：仓单模块（Warehouse）

#### 3.1 仓单签发（Mint）

| 项目                   | 内容                                                                                                                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 仓储方根据入库实物信息，在链上铸造唯一数字凭证                                                                                                                                                       |
| **对应接口**     | `POST /receipt/mint`（来源：仓单模块.md 第5节）                                                                                                                                                    |
| **上链等级**     | ✅**必须上链**                                                                                                                                                                                 |
| **上链原因**     | **资产确权**：电子仓单是实物资产数字化凭证，货权归属的法定依据；**不可篡改**：仓单重量、品名、仓储方等关键信息一旦上链不可篡改；**可追溯**：是后续背书、质押、拆分、流转的信任根基 |
| **上链内容**     | `on_chain_id`（链上TokenID）、`warehouse_id`、`owner_ent_id`、`warehouse_ent_id`、`goods_name`、`weight`、`unit`、`root_id`、`create_time`                                         |
| **上链时机**     | 仓储方确认入库后，执行Mint操作                                                                                                                                                                       |
| **链上逻辑**     | 状态更新：链上创建新Token，状态设为 `ACTIVE`；事件：抛出 `ReceiptMinted` 事件                                                                                                                    |
| **建议合约方法** | `function mintReceipt(uint256 warehouseId, address owner, string memory goodsName, uint256 weight, string memory unit, bytes32 extendedDataHash) external returns (uint256 tokenId);`              |
| **风险/建议**    | ⚠️ 需与链下 `StockOrder` 关联，确保实物与数字凭证一一对应；⚠️ `extendedDataHash` 应存储入库单附件的哈希值                                                                                    |

#### 3.2 发起背书转让

| 项目                   | 内容                                                                                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 货权人发起背书转让，通过"发起+签收"闭环转移货权                                                                                                                        |
| **对应接口**     | `POST /endorse/launch`（来源：仓单模块.md 第5节）                                                                                                                    |
| **上链等级**     | ✅**必须上链**                                                                                                                                                   |
| **上链原因**     | **货权转移**：涉及资产所有权的变更，必须上链确权；**法律效力**：背书转让具有法律效力，需链上存证；**责任追溯**：记录转让方与受让方，便于后续责任认定 |
| **上链内容**     | `receipt_id`、`transferor_ent_id`、`transferee_ent_id`、`signature_hash`、`endorse_time`                                                                     |
| **上链时机**     | 持有人发起背书转让，状态设为"待签收"                                                                                                                                   |
| **链上逻辑**     | 存证：记录背书转让意向，不立即转移所有权；事件：抛出 `EndorsementLaunched` 事件                                                                                      |
| **建议合约方法** | `function launchEndorsement(uint256 tokenId, address transferee, bytes32 signatureHash) external;`                                                                   |
| **风险/建议**    | ⚠️ 需校验 `is_locked=false`，质押中仓单不可转让；⚠️ 需校验仓单状态为 `ACTIVE`                                                                                  |

#### 3.3 背书签收确认

| 项目                   | 内容                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| **业务场景**     | 接收方签收确认，链上正式转移货权                                                           |
| **对应接口**     | `PUT /endorse/confirm`（来源：仓单模块.md 第5节）                                        |
| **上链等级**     | ✅**必须上链**                                                                       |
| **上链原因**     | **确权生效**：签收后货权正式转移，具有法律效力；**不可逆**：链上状态变更不可逆 |
| **上链内容**     | `endorse_id`、`tx_hash`、`finish_time`、新 `owner_ent_id`                          |
| **上链时机**     | 接收方点击确认签收                                                                         |
| **链上逻辑**     | 状态更新：`owner` 从转出方变更为接收方；事件：抛出 `EndorsementConfirmed` 事件         |
| **建议合约方法** | `function confirmEndorsement(uint256 tokenId) external;`                                 |
| **风险/建议**    | ⚠️ 需校验只有被背书人（`transferee`）才能确认；⚠️ 需设置有效期限                     |

#### 3.4 发起拆分申请

| 项目                | 内容                                                                   |
| ------------------- | ---------------------------------------------------------------------- |
| **业务场景**  | 持有人发起仓单拆分申请                                                 |
| **对应接口**  | `POST /receipt/split/apply`（来源：仓单模块.md 第5节）               |
| **上链等级**  | 🔔**建议上链**                                                   |
| **上链原因**  | 涉及资产拆分记录，便于后续追溯；拆分后需与原仓单建立关联关系           |
| **上链内容**  | `receipt_id`、`target_weights[]`、`apply_ent_id`、`apply_time` |
| **上链时机**  | 拆分申请创建时                                                         |
| **链上逻辑**  | 存证拆分申请意向                                                       |
| **风险/建议** | ⚠️ 该阶段仅为申请记录，可先链下执行；实际拆分执行（下一步）必须上链  |

#### 3.5 执行拆分/合并

| 项目                   | 内容                                                                                                                                                                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 仓储方执行拆分/合并操作，链上销毁旧Token并铸造新Token                                                                                                                                                                                  |
| **对应接口**     | `POST /receipt/op/execute`（来源：仓单模块.md 第5节）                                                                                                                                                                                |
| **上链等级**     | ✅**必须上链**                                                                                                                                                                                                                   |
| **上链原因**     | **资产重组**：链上Token的销毁与铸造是资产重组的法定操作；**重量守恒**：拆分需满足总重量不变，需链上校验；**不可篡改**：拆分后的新仓单继承不可篡改的父仓单历史                                                        |
| **上链内容**     | `source_receipt_ids`、`target_receipt_ids`、`total_weight`、`tx_hash`、新Token的 `parent_id`、`root_id`                                                                                                                    |
| **上链时机**     | 仓储方审核通过并执行操作                                                                                                                                                                                                               |
| **链上逻辑**     | 状态更新：旧Token设为 `SPLIT/MERGED`，新Token状态设为 `ACTIVE`；事件：抛出 `ReceiptSplit` 或 `ReceiptMerged` 事件                                                                                                              |
| **建议合约方法** | `function splitReceipt(uint256 sourceTokenId, uint256[] memory targetWeights) external returns (uint256[] memory newTokenIds);` / `function mergeReceipts(uint256[] memory sourceTokenIds) external returns (uint256 newTokenId);` |
| **风险/建议**    | ⚠️ 必须校验总重量守恒；⚠️ 需更新链下 `parent_id` 与 `root_id` 关联                                                                                                                                                             |

#### 3.6 质押锁定（Lock）

| 项目                   | 内容                                                                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 金融机构对仓单进行质押锁定，冻结资产流转权限                                                                                                                                     |
| **对应接口**     | `PATCH /receipt/lock`（来源：仓单模块.md 第5节）                                                                                                                               |
| **上链等级**     | ✅**必须上链**                                                                                                                                                             |
| **上链原因**     | **融资确权**：质押是融资的核心担保措施，锁定状态必须上链公示；**权利公示**：防止一物多押，保障金融机构优先受偿权；**流转限制**：链上锁定状态可被所有业务方查询 |
| **上链内容**     | `receipt_id`、`loan_id`、`lock_ent_id`、`lock_time`、`is_locked`（设为true）                                                                                           |
| **上链时机**     | 金融机构审核融资申请通过后                                                                                                                                                       |
| **链上逻辑**     | 状态更新：`is_locked` 设为 `true`；事件：抛出 `ReceiptLocked` 事件                                                                                                         |
| **建议合约方法** | `function lockReceipt(uint256 tokenId, uint256 loanId, address lender) external;`                                                                                              |
| **风险/建议**    | ⚠️ 需校验仓单未锁定且未质押；⚠️ 同一仓单只能被一家金融机构质押（建议在合约层校验）                                                                                           |

#### 3.7 还款解押（Unlock）

| 项目                   | 内容                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| **业务场景**     | 借款人还款后，金融机构解除质押锁定                                                                     |
| **对应接口**     | `PATCH /receipt/unlock`（来源：仓单模块.md 第5节）                                                   |
| **上链等级**     | ✅**必须上链**                                                                                   |
| **上链原因**     | **释放权利**：还款是质押解除的前提条件，释放行为必须上链公示；**状态变更**：恢复资产流动性 |
| **上链内容**     | `receipt_id`、`loan_id`、`unlock_time`、`is_locked`（设为false）                               |
| **上链时机**     | 金融机构校验还款流水后                                                                                 |
| **链上逻辑**     | 状态更新：`is_locked` 设为 `false`；事件：抛出 `ReceiptUnlocked` 事件                            |
| **建议合约方法** | `function unlockReceipt(uint256 tokenId, uint256 loanId) external;`                                  |
| **风险/建议**    | ⚠️ 需校验只有原锁定方（金融机构）才能解锁；⚠️ 需校验还款流水已确认                                 |

#### 3.8 申请核销出库

| 项目               | 内容                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| **业务场景** | 仓单持有人发起提货出库申请                                               |
| **对应接口** | `POST /receipt/burn/apply`（来源：仓单模块.md 第5节）                  |
| **上链等级** | 🔔**建议上链**                                                     |
| **上链原因** | 出库是仓单生命周期结束的起点，需留存申请记录；便于追溯出库意图和审批流程 |
| **上链内容** | `receipt_id`、`apply_ent_id`、`signature_hash`、`apply_time`     |
| **上链时机** | 持有人提交出库申请                                                       |

#### 3.9 核销终审（BURN）

| 项目                   | 内容                                                                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **业务场景**     | 仓储方审核执行出库，链上执行Burn销毁仓单                                                                                                         |
| **对应接口**     | `PUT /receipt/burn/confirm`（来源：仓单模块.md 第5节）                                                                                         |
| **上链等级**     | ✅**必须上链**                                                                                                                             |
| **上链原因**     | **资产终结**：出库后实物离场，数字凭证必须销毁；**防双花**：防止已出库仓单被重复使用；**闭环追溯**：是仓单全生命周期追溯的终点 |
| **上链内容**     | `receipt_id`、`tx_hash`、`burn_time`、Token状态设为 `BURNED`                                                                             |
| **上链时机**     | 仓储方审核确认后                                                                                                                                 |
| **链上逻辑**     | 状态更新：Token状态设为 `BURNED`，不可再流转；事件：抛出 `ReceiptBurned` 事件                                                                |
| **建议合约方法** | `function burnReceipt(uint256 tokenId) external;`                                                                                              |
| **风险/建议**    | ⚠️ 需校验提货指令的数字签名；⚠️ 需校验仓单未锁定                                                                                             |

#### 3.10 全路径溯源查询

| 项目                   | 内容                                                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 递归查询parent_id链条，还原资产完整演化图谱                                                                                                     |
| **对应接口**     | `GET /trace/receipt/{id}`（来源：仓单模块.md 第5节）                                                                                          |
| **上链等级**     | 🔔**建议上链**                                                                                                                            |
| **上链原因**     | 溯源是供应链金融的核心价值，支持多方对账与审计；链上数据天然适合构建可信溯源链                                                                  |
| **上链时机**     | 查询时从链上获取完整历史                                                                                                                        |
| **链上逻辑**     | 查询：从Token元数据中获取 `parent_id` 和 `root_id` 链；组合：关联链上事件日志还原完整路径                                                   |
| **建议合约方法** | `function getReceiptHistory(uint256 tokenId) external view returns (uint256[] memory parentChain, uint256 rootId, bytes[] memory eventLogs);` |

### 模块四：物流模块

#### 4.1 仓库提货确认

| 项目                   | 内容                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 起运仓管理员审核确定，原仓单重量核销                                                                                                                     |
| **对应接口**     | `POST /logistics/pickup`（来源：物流模块.md 第4节）                                                                                                    |
| **上链等级**     | ✅**必须上链**                                                                                                                                     |
| **上链原因**     | **货权转移起点**：提货是货物离库的法定确认，涉及物权的变动；**重量核销**：原仓单重量扣减必须有链上存证；**在途起点**：在途监管的起始点 |
| **上链内容**     | `voucher_no`、`receipt_id`、`transport_quantity`、`pickup_time`、`auth_signature`                                                              |
| **上链时机**     | 仓库管理员确认提货                                                                                                                                       |
| **链上逻辑**     | 存证：记录提货事件；状态更新：物流单状态转为 `IN_TRANSIT`；事件：抛出 `GoodsPickedUp` 事件                                                           |
| **建议合约方法** | `function confirmPickup(uint256 voucherId, uint256 receiptId, uint256 quantity, bytes signature) external;`                                            |
| **风险/建议**    | ⚠️ 需校验地理围栏（<500m）和司机实名信息；⚠️ 部分提货时需处理仓单重量扣减                                                                            |

#### 4.2 到货入库申请

| 项目                   | 内容                                                                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 货物送达目的地仓库，生成新仓单或增量入库                                                                                                                                                                 |
| **对应接口**     | `POST /logistics/arrive`（来源：物流模块.md 第4节）                                                                                                                                                    |
| **上链等级**     | ✅**必须上链**                                                                                                                                                                                     |
| **上链原因**     | **资产新生/增量**：到货意味着新仓单生成或原仓单增量，是资产的确权时刻；**物流闭环**：完成位移全过程，是金融模块生成应收款的触发条件                                                          |
| **上链内容**     | `voucher_no`、`target_receipt_id`、`action_on_arrival`（1-生成新仓单/2-增量入库）、`arrive_time`                                                                                                 |
| **上链时机**     | 货物到达目的地仓库，管理员确认                                                                                                                                                                           |
| **链上逻辑**     | 分支处理：模式1调用合约 `mintReceipt` 生成新仓单；模式2调用合约 `addQuantity` 增量；事件：抛出 `GoodsArrived` 事件                                                                                 |
| **建议合约方法** | `function createReceiptOnArrival(uint256 voucherId, address owner, uint256 quantity) external returns (uint256 tokenId);` / `function addQuantity(uint256 tokenId, uint256 addedQuantity) external;` |
| **风险/建议**    | ⚠️ 需校验物流单状态为"运输中"；⚠️ 增量模式需校验目标仓单存在且未锁定                                                                                                                                 |

### 模块五：金融模块

#### 5.1 应收款预生成

| 项目                   | 内容                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **业务场景**     | 物流送达时自动调用，生成基于实物价值的"原始应收款"                                                                                                                                         |
| **对应接口**     | `POST /finance/receivable/generate`（来源：金融模块.md 第4节）                                                                                                                           |
| **上链等级**     | ✅**必须上链**                                                                                                                                                                       |
| **上链原因**     | **债权确权**：应收款是数字债权的法定凭证，必须上链确权；**金额锚定**：初始金额一旦上链，不可单方面修改；**转让基础**：是后续债权转让、融资的底层资产                     |
| **上链内容**     | `receivable_no`、`creditor_ent_id`、`debtor_ent_id`、`initial_amount`、`source_voucher_id`、`business_scene`、`due_date`                                                     |
| **上链时机**     | 物流状态变为"已送达"时自动触发                                                                                                                                                             |
| **链上逻辑**     | 存证：创建应收款记录；事件：抛出 `ReceivableGenerated` 事件                                                                                                                              |
| **建议合约方法** | `function createReceivable(uint256 receivableNo, address creditor, address debtor, uint256 amount, uint256 dueDate, bytes32 sourceVoucherHash) external returns (uint256 receivableId);` |
| **风险/建议**    | ⚠️ 需与仓单模块联动，确保应收款金额与仓单价值一致；⚠️ 建议设置"待确认"状态，由债务人确认后生效                                                                                         |

#### 5.2 账单确权确认

| 项目                   | 内容                                                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **业务场景**     | 债务人（买方）对账单进行数字签名确认                                                                                                                                           |
| **对应接口**     | `POST /finance/receivable/confirm`（来源：金融模块.md 第4节）                                                                                                                |
| **上链等级**     | ✅**必须上链**                                                                                                                                                           |
| **上链原因**     | **法律效力**：债务人签字确认后，应收款具备法律追偿效力；**不可抵赖**：链上签名无法否认，是诉讼仲裁的法定证据；**状态生效**：确认后状态从"待确认"转为"生效中" |
| **上链内容**     | `receivable_id`、`signature`、`confirm_time`、状态更新为 `ACTIVE`                                                                                                      |
| **上链时机**     | 债务人完成签名确认                                                                                                                                                             |
| **链上逻辑**     | 状态更新：状态从 `PENDING` 转为 `ACTIVE`；事件：抛出 `ReceivableConfirmed` 事件                                                                                          |
| **建议合约方法** | `function confirmReceivable(uint256 receivableId, bytes signature) external;`                                                                                                |
| **风险/建议**    | ⚠️ 需校验只有债务人（`debtor_ent_id`）才能确认；⚠️ 需设置确认有效期，超时自动失效                                                                                        |

#### 5.3 金额动态修正

| 项目                   | 内容                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 处理物流损耗或仓单拆分时的金额调整                                                                                               |
| **对应接口**     | `PATCH /finance/receivable/adjust`（来源：金融模块.md 第4节）                                                                  |
| **上链等级**     | ✅**必须上链**                                                                                                             |
| **上链原因**     | **金额变更**：应收款金额调整必须有链上存证，防止争议；**联动一致性**：仓单拆分时应收款必须同步调整，需链上保证原子性 |
| **上链内容**     | `receivable_id`、`adjust_type`（1-物流损耗扣减/2-仓单拆分同步）、`adjust_amount`、`adjusted_amount`                      |
| **上链时机**     | 物流损耗确认或仓单拆分完成时                                                                                                     |
| **链上逻辑**     | 状态更新：更新 `adjusted_amount`；事件：抛出 `ReceivableAdjusted` 事件                                                       |
| **建议合约方法** | `function adjustReceivable(uint256 receivableId, uint8 adjustType, uint256 adjustAmount) external;`                            |
| **风险/建议**    | ⚠️ 需与仓单模块建立事务一致性机制；⚠️ 调整后需重新计算待还余额                                                               |

#### 5.4 现金分批还款

| 项目                   | 内容                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **业务场景**     | 记录债务人还款，增加已回收金额                                                                                                                                     |
| **对应接口**     | `POST /finance/repay/cash`（来源：金融模块.md 第4节）                                                                                                            |
| **上链等级**     | ✅**必须上链**                                                                                                                                               |
| **上链原因**     | **债务清偿**：还款是债务减少的核心凭证，必须上链存证；**余额变更**：待还余额减少必须有链上记录；**释放资产**：还款达到比例后可能触发质押仓单释放 |
| **上链内容**     | `receivable_id`、`amount`、`payment_voucher`、`repay_time`、`collected_amount`、`balance_unpaid`                                                       |
| **上链时机**     | 还款到账并校验通过                                                                                                                                                 |
| **链上逻辑**     | 状态更新：根据还款比例更新状态（部分还款/已结清）；事件：抛出 `RepaymentRecorded` 事件                                                                           |
| **建议合约方法** | `function recordRepayment(uint256 receivableId, uint256 amount, bytes32 paymentVoucherHash) external;`                                                           |
| **风险/建议**    | ⚠️ 需校验还款金额 ≤ 待还余额；⚠️ 需触发信用模块更新评分                                                                                                       |

#### 5.5 仓单抵债核销

| 项目                   | 内容                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **业务场景**     | 债务人无力还款，以仓单所有权冲抵债务                                                                                                                               |
| **对应接口**     | `POST /finance/repay/offset`（来源：金融模块.md 第4节）                                                                                                          |
| **上链等级**     | ✅**必须上链**                                                                                                                                               |
| **上链原因**     | **以物抵债**：涉及资产所有权转移，必须上链确权；**债权消灭**：债务通过物抵方式清偿，链上状态必须同步；**双重联动**：同时触发仓单模块的所有权变更 |
| **上链内容**     | `receivable_id`、`receipt_id`、`offset_price`、`offset_time`、状态更新为 `SETTLED`                                                                       |
| **上链时机**     | 债权人确认抵债申请                                                                                                                                                 |
| **链上逻辑**     | 状态更新：应收款状态设为 `SETTLED`；联动：调用仓单合约转移所有权；事件：抛出 `DebtOffsetByCollateral` 事件                                                     |
| **建议合约方法** | `function offsetDebtWithCollateral(uint256 receivableId, uint256 tokenId, uint256 offsetValue) external;`                                                        |
| **风险/建议**    | ⚠️ 需校验仓单所有权属于债务人；⚠️ 需校验抵债价值 ≥ 待还余额（或部分抵债）                                                                                     |

### 模块六：信用管理模块

#### 6.1 违约事件上报

| 项目                   | 内容                                                                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **业务场景**     | 金融模块发现逾期，或风控发现偏航时，自动触发扣分                                                                                                                                 |
| **对应接口**     | `POST /credit/event/report`（来源：信用管理模块.md 第3节）                                                                                                                     |
| **上链等级**     | ✅**必须上链**                                                                                                                                                             |
| **上链原因**     | **信用溯源**：信用评分调整必须有法定存证，不可事后篡改；**奖惩公示**：违约记录上链公示，对其他主体形成信用约束；**审计合规**：满足金融监管对信用评分的审计要求 |
| **上链内容**     | `ent_id`、`event_type`（逾期/偏航/撤单/异常）、`event_score`、`report_source`、`report_time`、`new_credit_score`                                                     |
| **上链时机**     | 违约行为被确认时（如逾期超过due_date）                                                                                                                                           |
| **链上逻辑**     | 状态更新：更新 `credit_score`；事件：抛出 `CreditEventReported` 事件                                                                                                         |
| **建议合约方法** | `function reportCreditEvent(uint256 entId, uint8 eventType, int256 scoreChange, string memory evidenceHash) external;`                                                         |
| **风险/建议**    | ⚠️ 需与金融模块、物流模块建立事件触发机制；⚠️ 建议设置每日/每次最大扣分上限                                                                                                  |

#### 6.2 信用等级重算

| 项目               | 内容                                                                               |
| ------------------ | ---------------------------------------------------------------------------------- |
| **业务场景** | 系统每月根据企业的交易频次、履约率自动更新分数和等级                               |
| **对应接口** | `PATCH /credit/reevaluate`（来源：信用管理模块.md 第3节）                        |
| **上链等级** | 🔔**建议上链**                                                               |
| **上链原因** | 定期评分调整需要存证，便于申诉与审计；等级变更可能触发业务规则变化（如质押率调整） |
| **上链内容** | `ent_id`、`new_score`、`new_level`、`eval_time`                            |
| **上链时机** | 每月定时任务执行                                                                   |
| **链上逻辑** | 状态更新：更新评分与等级；事件：抛出 `CreditLevelRecalculated` 事件              |

## 三、问题检查结果

### 3.1 漏上链风险点（标注文档来源）

| 序号 | 风险点                         | 文档来源               | 说明                                                                                 |
| ---- | ------------------------------ | ---------------------- | ------------------------------------------------------------------------------------ |
| 1    | **入库单申请** 未上链    | Warehouse模块.md 第5节 | 入库单是仓单签发的源头数据，重量、品名等核心数据目前仅存链下，存在源头数据被篡改风险 |
| 2    | **物流指派任务** 未上链  | 物流模块.md 第4节      | 司机身份、车牌号、动态二维码等关键信息未上链，可能导致在途货物被掉包风险             |
| 3    | **物流状态追踪** 未上链  | 物流模块.md 第4节      | 在途位置更新、偏航预警等数据仅存链下，无法满足"物流轨迹存证"需求                     |
| 4    | **还款释放规则** 未上链  | 金融模块.md 第4节      | "还款达到比例自动释放对应价值货物"的规则未在链上固化，可能导致释放不透明             |
| 5    | **信用额度锁死** 未上链  | 信用管理模块.md 第3节  | 超额度时拦截物流单的校验逻辑未上链，可能被应用层绕过                                 |
| 6    | **企业登录/登出** 未上链 | 企业管理模块.md 第2节  | 关键操作未留存审计痕迹，无法满足金融合规要求                                         |

### 3.2 过度上链冗余点（标注文档来源）

| 序号 | 冗余点                            | 文档来源              | 说明                                               |
| ---- | --------------------------------- | --------------------- | -------------------------------------------------- |
| 1    | **员工注册** 建议不上链     | 用户模块.md 第2节     | 纯内部账号管理，与资产无关，建议链下处理即可       |
| 2    | **修改个人信息** 建议不上链 | 用户模块.md 第2节     | 个人信息变更不涉及资产/确权，链下处理即可          |
| 3    | **生成邀请码** 建议不上链   | 企业管理模块.md 第2节 | 邀请码是内部运营工具，不涉及核心业务，链下处理即可 |
| 4    | **获取信用画像** 查询类接口 | 信用管理模块.md 第3节 | 仅展示用，无需上链，链上链下数据一致即可           |

### 3.3 上链逻辑不合理点（标注文档来源）

| 序号 | 问题点                             | 文档来源              | 说明                                                                       |
| ---- | ---------------------------------- | --------------------- | -------------------------------------------------------------------------- |
| 1    | **拆分申请与执行分离**       | 仓单模块.md 第5节     | 申请（链下）与执行（链上）分离可能导致数据不一致，建议合并为原子操作       |
| 2    | **背书转让两阶段确认**       | 仓单模块.md 第5节     | 发起+确认两阶段设计正确，但中间状态"待签收"在链上未明确体现，可能导致争议  |
| 3    | **应收款与仓单拆分联动缺失** | 金融模块.md 第1节     | 文档提到"仓单拆分后应收款自动按比例拆分"，但未明确触发机制和事务一致性保障 |
| 4    | **信用评分计算逻辑未上链**   | 信用管理模块.md 第1节 | 评分计算规则（加分/扣明细）未在链上存证，可能引发评分争议                  |
| 5    | **物流损耗判定标准未上链**   | 金融模块.md 第1节     | "合理损耗范围（如5%）"的标准未在链上固化，可能导致损耗扣减争议             |

## 四、整体上链方案建议

### 4.1 核心上链主线

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                              核心上链资产三条线                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│  1. 身份线：企业注册 → 链上身份确立                                           │
│     └─→ EnterpriseRegistryV2.registerEnterprise()                          │
│                                                                             │
│  2. 资产线：仓单签发 → 背书/拆分/质押 → 核销                                 │
│     └─→ WarehouseReceiptV2.mint/burn/lock/unlock/split/merge              │
│                                                                             │
│  3. 债权线：应收款生成 → 确认 → 调整 → 还款/抵债 → 结清                      │
│     └─→ ReceivableV2.create/adjust/repay/offset                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 合约设计方向

| 合约                           | 核心职责       | 建议方法                                                                                                                                                                 |
| ------------------------------ | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **EnterpriseRegistryV2** | 企业身份管理   | `registerEnterprise()`, `getEnterpriseInfo()`, `getAssetBalance()`                                                                                                 |
| **WarehouseReceiptV2**   | 仓单全生命周期 | `mintReceipt()`, `burnReceipt()`, `lockReceipt()`, `unlockReceipt()`, `splitReceipt()`, `mergeReceipts()`, `launchEndorsement()`, `confirmEndorsement()` |
| **ReceivableV2**         | 应收款管理     | `createReceivable()`, `confirmReceivable()`, `adjustReceivable()`, `recordRepayment()`, `offsetDebtWithCollateral()`                                           |
| **CreditLimitV2**        | 信用额度管理   | `reportCreditEvent()`, `calculateCreditScore()`, `checkCreditLimit()`                                                                                              |

### 4.3 链下接口改造点

| 模块 | 改造点       | 建议                                                                   |
| ---- | ------------ | ---------------------------------------------------------------------- |
| 物流 | 物流指派任务 | 建议新增链上存证：`logistics/assign` → 上链记录司机身份与二维码哈希 |
| 物流 | 在途状态更新 | 建议新增链上事件：`logistics/track` → 定时上报位置哈希              |
| 信用 | 额度锁死逻辑 | 建议合约层新增：`checkLimitBeforeLogistics()` 供链下调用             |
| 金融 | 还款释放规则 | 建议合约层固化：`releaseCollateralOnRepay()` 自动执行释放            |
| 仓单 | 入库单源头   | 建议新增：`stock/in/apply` → 上链存证入库单哈希                     |

### 4.4 上链判定矩阵汇总

| 模块     | 必须上链                                 | 建议上链                 | 不建议上链             |
| -------- | ---------------------------------------- | ------------------------ | ---------------------- |
| 企业管理 | 企业注册、注销资产校验                   | 详情查询                 | 登录、密码修改、邀请码 |
| 用户     | -                                        | 角色分配                 | 注册、登录、信息修改   |
| 仓单     | Mint、Burn、Lock、Unlock、背书、拆分执行 | 拆分申请、出库申请、溯源 | -                      |
| 物流     | 提货确认、到货入库                       | -                        | 创建、指派、状态追踪   |
| 金融     | 生成、确认、调整、还款、抵债             | -                        | 流水查询               |
| 信用     | 违约事件上报                             | 等级重算                 | 画像查询               |
