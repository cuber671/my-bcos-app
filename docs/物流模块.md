### 1. 模块定位

Logistics 模块是物流金融中资产“位移过程”的数字化映射与风控核心。它通过 **电子提货委派单 (DPDO)** 建立货主、物流方与仓库之间的授权链条，支持 **纯物理移库** 与 **贸易转让配送** 两种核心场景。利用区块链存证与地理围栏技术，确保资产在离库在途期间的真实性与不可篡改性。

---

### 2. 核心业务逻辑

本模块专门处理货物在物理空间移动时的“证货一致”问题，根据您的需求，业务逻辑分为以下三个严格场景：

#### 场景 1：直接移库（从仓库 A 到仓库 B）

 **场景描述** ：货主不换，只是把货物从一个仓库搬到另一个仓库。

* **业务流程** ：

1. **发起** ：货主指定目标仓库和物流公司。
2. **提货** ：司机在仓库 A 扫码取货，仓库 A 的数字仓单记录注销。
3. **送达** ：货物到达仓库 B 后，仓库 B 管理员扫码确认。

* **仓单操作** ：**【涉及仓单操作】** 系统会自动在仓库 B 生成一张新的数字仓单。虽然货物的“家”变了，但它的电子证件（包含重量、品名、来源记录）会自动接续，保证货主手里的资产凭证不中断。

---

#### 场景 2：转让后移库（先卖掉，买家再换仓库）

 **场景描述** ：货主 A 把货卖给了买家 B，买家 B 觉得原来的仓库不方便，要求物流公司拉到新仓库。

* **业务流程** ：

1. **转让** ：货主 A 在系统中完成“背书转让”，此时货权已经正式属于买家 B。
2. **发起移库** ：由**新买家 B** 下达物流指令，指定目的地为新的监管仓库。
3. **运输** ：物流方去旧仓库提货，送往新仓库。

* **仓单操作** ：**【涉及仓单操作】** 货物到达新仓库后，系统会自动为**买家 B** 生成一张新地址的数字仓单。这完成了“货权转让 + 物理位移”的完整闭环，新买家拿到了新仓库开具的电子凭证。

---

#### 场景 3：发往指定仓库（企业发货入库）

 **场景描述** ：企业通过物流公司，将自己手中的实物货物发送到平台的监管仓库挂账。

* **业务流程** ：

1. **发起** ：企业（发货方）填好货物信息，指派物流公司运往指定的监管仓库。
2. **运输** ：物流公司负责装车并拉往目的地。
3. **入库** ：监管仓库收到货后，核对实物数量、质量。

* **仓单操作** ：**【涉及仓单操作】** 只要仓库管理员点击确认入库，系统就会根据物流单上的信息 **实时生成一张数字仓单** 。这标志着实物货物正式转换成了可以在平台上流转、抵押的“数字资产”。

### 3. 操作权限矩阵 (RBAC + ABAC)

| **业务动作**        | **物流企业 (Carrier)** | **货主/买方 (Owner/Buyer)** | **仓储方 (Warehouse)** | **核心约束条件 (ABAC & 状态机)**               |
| ------------------------- | ---------------------------- | --------------------------------- | ---------------------------- | ---------------------------------------------------- |
| **签发移库委派单**  | ❌                           | **✅ 发起**                 | ❌                           | 仓单状态必须为在库，且所有权归属发起方               |
| **关联转让委派**    | ❌                           | **✅ 联动**                 | ❌                           | 必须存在已生效的背书转让记录 (`endorse_id`)        |
| **调度指派人员**    | **✅ 操作**            | ❌                                | ❌                           | 仅限被授权的物流企业；需绑定司机身份与车牌           |
| **提货核验 (取货)** | ⚠️**出示凭证**       | ❌                                | **✅ 审核**            | 校验地理围栏 (**$<500m$**)；校验司机实名信息 |
| **在途状态更新**    | ✅**自动上报**         | ⚠️ 查看                         | ⚠️ 查看                    | 仅限 `IN_TRANSIT`状态；偏航时触发系统预警          |
| **到货签收 (交付)** | ❌                           | **✅ 签收**                 | **✅ 确认**            | 移库由新仓库确认；销售配送由收货人签名               |

### 4. 数据字典

### 电子物流委派单设计表

| **字段名**                 | **类型** | **约束**         | **说明**                                                             |
| -------------------------------- | -------------- | ---------------------- | -------------------------------------------------------------------------- |
| **`id`**                 | `Long`       | `PK`, 雪花算法       | 委派单唯一主键 ID。                                                        |
| **`voucher_no`**         | `String`     | `Unique`,`NotNull` | 业务展示编号（如：DPDO20260220001）。                                      |
| **`business_scene`**     | `Integer`    | `NotNull`            | **场景类型** ：1-直接移库；2-转让后移库；3-发货入库。                |
| **`receipt_id`**         | `Long`       | `Nullable`           | **关联原仓单 ID** ：场景 1 和 2 必填。                               |
| **`endorse_id`**         | `Long`       | `Nullable`           | **背书 ID** ：场景 2 必填，用于核实买家身份。                        |
| **`transport_quantity`** | `Decimal`    | `NotNull`            | **本次运输数量** ：核心字段！记录本次拉走的具体数值。                |
| **`unit`**               | `String`     | `NotNull`            | **计量单位** ：如“吨”、“千克”、“件”。                          |
| **`owner_ent_id`**       | `Long`       | `NotNull`            | **授权企业** ：发起物流申请的货主/买方 ID。                          |
| **`carrier_ent_id`**     | `Long`       | `NotNull`            | **承运企业** ：指定的物流方公司 ID。                                 |
| **`source_wh_id`**       | `Long`       | `NotNull`            | **起运地 ID** ：货物目前存放的仓库。                                 |
| **`target_wh_id`**       | `Long`       | `Nullable`           | **目的地仓库 ID** ：发往监管仓时必填（触发新证操作）。               |
| **`action_on_arrival`**  | `Integer`    | `Default: 1`         | **到货处理动作** ：1-生成新仓单；2-并入已有仓单（增量入库）。        |
| **`target_receipt_id`**  | `Long`       | `Nullable`           | **目标仓单 ID** ：当执行“增量入库”时，指定并入哪张老单。           |
| **`auth_signature`**     | `Text`       | `NotNull`            | **货主数字签名** ：授权物流方拉走 `transport_quantity`数量的凭证。 |
| **`status`**             | `Integer`    | `Default: 1`         | **状态** ：1-待指派, 2-已调度, 3-运输中, 4-已交付, 5-已失效。        |
| **`valid_until`**        | `DateTime`   | `NotNull`            | **凭证有效期** ：防止过期授权被恶意使用。                            |
| **`create_time`**        | `LocalDateTime`   | `NotNull`            | **创建时间** ：记录委派单创建时间。                            |

### 物流模块 API 接口设计表

| **接口名称**       | **路径 (Method)**     | **必填字段**                                                        | **后台逻辑说明**                                                                                                                                                                                                                  |
| ------------------------ | --------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **创建物流委派单** | `/logistics/create`(POST) | `business_scene`,`receipt_id`,`transport_quantity`,`target_wh_id` | **发起运输申请** ：用户填写要拉走的重量。如果是“部分提货”，系统会检查拉走的数量是否超过仓单余额。此时，原仓单中对应的数量会被“锁定”，不能再卖或再抵押。                                                                       |
| **物流指派任务**   | `/logistics/assign`(POST) | `voucher_id`,`driver_id`,`vehicle_no`                               | **派单给司机** ：物流公司确定执行人。系统生成带动态加密的二维码（钥匙），并绑定该次运输的货物品名与重量。                                                                                                                         |
| **仓库提货确认**   | `/logistics/pickup`(POST) | `auth_code`,`source_wh_id`                                            | **出库核销** ：起运仓管理员审核确定。 **核心逻辑** ：审核确定后，原仓单的重量会 **实时扣减** （如果全拉走则原单注销，拉一部分则原单减去相应重量）。                                                                   |
| **到货入库申请**   | `/logistics/arrive`(POST) | `voucher_id`,`action_type`,`target_receipt_id`(可选)                | **送达交接/发证** ：货物到达目的地仓库。系统根据 `action_type`（到货处理动作）决定下一步：``1. **重铸模式** ：自动在该仓库生成一张新仓单。``2. **增量模式** ：不发新证，直接在老仓单（`target_receipt_id`）上增加重量。 |
| **物流状态追踪**   | `/logistics/track`(GET)   | `voucher_id`                                                            | **全流程监控** ：查看当前是在派单、运输中还是已入库。包含实时地理位置校验，确保“资产位移”真实可靠。                                                                                                                             |
