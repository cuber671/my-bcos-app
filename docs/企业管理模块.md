# 一、数据字典

## 1. 基础信息字段

| **字段名**          | **类型** | **约束**          | **说明**                                          |
| ------------------------- | -------------- | ----------------------- | ------------------------------------------------------- |
| **ent_id**          | `Long`       | **PK, ASSIGN_ID** | 全局唯一标识，采用**MyBatis Plus 雪花算法**生成。 |
| **enterprise_name** | `String`     | Not Null                | 企业法定全称，用于在区块链票据凭证上展示。              |
| **org_code**        | `String`     | Unique                  | 统一社会信用代码，企业在法律层面的唯一识别码。          |
| **local_address**   | `String`     | Not Null                | 企业实际地址                                            |
| **contact_phone**   | `String`     | -                       | 企业经办人联系电话。                                    |

## 2. 账户与安全字段

| **字段名**       | **类型** | **约束** | **说明**                                                                                             |
| ---------------------- | -------------- | -------------- | ---------------------------------------------------------------------------------------------------------- |
| **username**     | `String`     | Unique         | 系统登录账号。                                                                                             |
| **password**     | `String`     | Not Null       | 登录密码，数据库仅存储经**BCrypt**或**SM3**脱敏后的 Hash 值。                                  |
| **pay_password** | `String`     | Not Null       | **交易密码** ，用于敏感操作（如签发、拆票）时解密私钥的二次验证。                                    |
| **ent_role**     | `Integer`    | Not Null       | 业务角色：`1-核心企业`、`2-现货交易平台`、`3-供应商`、`6-金融机构`、`9-仓储方`、`12-物流方`。 |

## 3. 区块链身份字段

| **字段名**                | **类型** | **存储建议** | **说明**                                                                                        |
| ------------------------------- | -------------- | ------------------ | ----------------------------------------------------------------------------------------------------- |
| **blockchain_address**    | `String`     | 明文               | **区块链公开地址**(0x...)。作为链上身份标识，用于关联合约中的 `msg.sender`及资产余额查询。    |
| **encrypted_private_key** | `Text`       | **AES加密**  | **加密存储的私钥** 。由 Java 后端生成并加密，严禁明文存储。签名时需配合系统密钥或交易密码解密。 |

## 4. 审计与状态字段

| **字段名**      | **类型** | **默认值**  | **说明**                                                                                                            |
| --------------------- | -------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **status**      | `Integer`    | 1                 | 账户状态：`0-待审核`、`1-正常`、`2-冻结`、`3-注销中`、`4-已注销`。 |
| **create_time** | `DateTime`   | CURRENT_TIMESTAMP | 记录创建时间。                                                                                                            |
| **update_time** | `DateTime`   | -                 | 记录最后一次修改时间。                                                                                                    |

# 二、企业模块 API 接口

| **接口名称**         | **路径**                   | **必填字段**                                     | **后台逻辑**                                                                                                                                                               |
| -------------------------- | -------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **企业注册**         | `POST /ent/register`           | `username`,`password`,`pay_password`,`enterpriseName`,`orgCode` | **逻辑** ：生成雪花ID；调用 SDK **生成区块链地址与私钥** ；私钥和登录密码经过加密后存储数据库，<br />企业状态设为 `PENDING`后续由管理员审核操作。                  |
| **企业登录**         | `POST /ent/login`              | `username`, `password`                            | **逻辑** ：校验成功后颁发 JWT，载荷包含 `entId`,`entRole`。                                                                                                            |
| **发起注销**         | `POST /ent/cancellation/apply` | `reason`                                             | **逻辑** ：校验该企业链上资产余额是否清零。若有未结清凭证，禁止申请。状态变更为 `NORMAL -> CANCELLING`。<br />直接从 JWT 解析 `entId` ，严禁通过传参获取，防止越权。 |
| **修改登录密码**     | `PUT /ent/password/login`      | `oldPwd`,`newPwd`                                  | **逻辑** ：直接从 JWT 解析 `entId`来修改对应的密码常规 BCrypt/SM3 散列值更新。                                                                                           |
| **重置交易密码**     | `PUT /ent/password/pay`        | `oldPayPwd`,`newPayPwd`                  | **逻辑** ：由于交易密码涉及私钥解密，重置后需记录审计日志，防范账号被盗后的资产转移。直接从 JWT 解析 `entId`。                                                                                      |
| **获取企业详情**     | `GET /ent/info_detail`         | -                                                      | **逻辑** ：直接从 JWT 解析 `entId`查询，严禁通过传参获取，<br />防止越权。返回基础资料、角色、状态以及区块链公开地址。                                                   |
| **生成邀请码**       | `GET /ent/invite-codes`        | -                                                      | **逻辑** ：用于用户进行注册时使用的必填字段。直接从 JWT 解析 `entId`来生成对应                                                                                           |
| **删除邀请码**       | `DELETE /ent/invite-codes`     | `codeId`                                             | **逻辑** ：删除指定邀请码，邀请码删除后失效。                                                                                                                              |
| **员工列表**         | `GET /ent/info_user`           | -                                                      | **逻辑** ：直接从 JWT 解析 `entId`分页查询所有关联该企业 ID 的用户信息。                                                                                                 |
| **获取指定用户信息** | `GET /ent/get_user`            | `userId`                                             | **逻辑** ：查询该企业内指定员工的信息                                                                                                                                      |
| **管理企业用户**     | `PUT /ent/users/{id}`          | `userId`                                             | **逻辑** ：用于修改员工信息（如权限或职务）或移除成员。                                                                                                                    |

## 企业邀请码

这种设计支持“一企多码”，可以追踪谁邀请了谁、码是否过期、被使用了多少次。

### 字段设计

| **字段名**             | **类型** | **说明**         | **作用**                                                 |
| ---------------------------- | -------------- | ---------------------- | -------------------------------------------------------------- |
| **`code_id`**        | `Long`       | 主键 ID                | 唯一标识。建议使用 `UUID` 截取或 `NanoId` 配合自定义字符集 |
| **`inviter_ent_id`** | `Long`       | 发起邀请的企业 ID      | 记录谁发出的邀请（如核心企业 ID）                              |
| **`code`**           | `String`     | **邀请码字符串** | 唯一索引，建议 6-8 位大写字母+数字                             |
| **`max_uses`**       | `Integer`    | 最大使用次数           | 限制该码能邀请多少个供应商                                     |
| **`used_count`**     | `Integer`    | 已使用次数             | 实时统计，防止超额                                             |
| **`expire_time`**    | `DateTime`   | 到期时间               | 超过此时间该码自动失效                                         |
| **`status`**         | `Integer`    | 状态                   | 0: 禁用, 1: 启用, 2: 已用罄。默认为 1                          |
| **`remark`**         | `String`     | 备注                   | 例如：“2026年夏季供应商入驻专项”                             |
| **`create_time`**    | `DateTime`   | 创建时间               | 审计需要                                                       |
