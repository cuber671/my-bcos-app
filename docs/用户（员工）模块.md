## 一、 数据字典：

### 1. 基础信息字段

| **字段名**        | **类型** | **约束** | **说明**                                     |
| ----------------------- | -------------- | -------------- | -------------------------------------------------- |
| **user_id**       | `Long`       | PK, ASSIGN_ID  | 雪花算法生成。                                     |
| **enterprise_id** | `Long`       | Not Null       | **外键** ：所属企业 ID，通过邀请码自动绑定。 |
| **real_name**     | `String`     | Not Null       | 用户真实姓名。                                     |
| **phone**         | `String`     | Unique         | 手机号，可用于登录及接收预警短信。                 |
| **email**         | `String`     | Unique         | 企业邮箱。                                         |

### 2. 账户与安全字段

| **字段名**    | **类型** | **约束**   | **说明**                                                    |
| ------------------- | -------------- | ---------------- | ----------------------------------------------------------------- |
| **username**  | `String`     | Unique, Not Null | 系统登录账号（员工工号或自定义）。                                |
| **password**  | `String`     | Not Null         | 登录密码（BCrypt 散列值）。                                       |
| **user_role** | `String`     | Not Null         | 内部职能：`ADMIN-管理员`,`FINANCE-财务`,`OPERATOR-业务员`。 |

### 3. 审计与状态字段

| **字段名**          | **类型** | **默认值**  | **说明**                                                              |
| ------------------------- | -------------- | ----------------- | --------------------------------------------------------------------------- |
| **status**          | `Integer`    | 2                 | `1-待审核`，`2-正常`，`3-冻结`，`4-注销中`，`5-已注销`。 |
| **last_login_time** | `String`     | -                 | 最后登录时间，用于安全审计。                                                |
| **create_time**     | `DateTime`   | CURRENT_TIMESTAMP | 入职/注册时间。                                                             |
| **update_time**     | `DateTime`   | -                 | 最后资料更新时间。                                                          |

## 二、 用户模块 API 接口设计

### 1. 注册与入职 (Onboarding)

| **接口名称** | **路径 (Method)** | **必填字段**                       | **后台逻辑**                                                                                                                            |
| ------------------ | ----------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **员工注册** | `POST /user/register` | `username`,`password`,`inviteCode` | **逻辑** ：校验邀请码有效性，提取对应的 `enterpriseId`写入实体，<br />完成关联，状态默认为 `1-注册中（待审核）`等待企业管理员审核。 |
| **员工登录** | `POST /user/login`    | `username`,`password`                | **逻辑** ：校验成功后颁发 JWT，载荷包含 `userId`,`entId`,`userRole`。                                                             |

### 2. 个人信息管理

| **接口名称**     | **路径 (Method)**      | **必填字段**       | **权限与一致性校验**                                                                                                                  |
| ---------------------- | ---------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **获取个人资料** | `GET /user/profile`        | -                        | **安全** ：直接从 JWT 解析 `userId`查询，严禁通过传参获取，防止越权。                                                               |
| **修改个人信息** | `PUT /user/update`         | `username`,`email`   | **逻辑** ：仅允许修改非敏感字段。                                                                                                     |
| **修改登录密码** | `POST /user/password`      | `oldPwd`,`newPwd`    | **逻辑** ：直接从 JWT 解析 `userId`查询，校验旧密码后更新，并建议强制 Token 失效重新登录。。                                        |
| **发起注销申请** | `POST /user/cancel/apply`  | `reason`, `password` | **逻辑** ：直接从 JWT 解析 `userId`进行身份确认，校验登录密码。检查该员工是否还有未处理完的审批任务（如果是财务角色），若有则驳回。 |
| **撤回注销申请** | `POST /user/cancel/revoke` | -                        | **逻辑** ：状态回滚至 `2-正常`。仅在管理员审批前有效。                                                                              |

### 3. 企业内管理

| **接口名称**      | **路径 (Method)**    | **必填字段**      | **说明**                                                                                          |
| ----------------------- | -------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------- |
| **分配员工角色**  | `PUT /user/assign_role`  | `userId`,`userRole` | **安全** ：校验当前登录者必须是该员工所属企业的管理员。                                           |
| **禁用/启用员工** | `PUT /user/status`       | `userId`,`status`   | **逻辑** ：员工离职或账号异常时强制失效。                                                         |
| **强制禁用员工**  | `PUT /user/disable/{id}` | `userId`              | **逻辑** ：将状态改为 `3-冻结`。该操作立即生效，拦截器会识别其 JWT 为无效，强制下线。           |
| **确认离职/删除** | `DELETE /user/{id}`      | `userId`              | **逻辑** ：物理删除用户。 **关键点** ：保留该用户历史操作的审计日志，但禁止删除其数据信息。 |
