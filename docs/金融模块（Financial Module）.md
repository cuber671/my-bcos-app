进入 **金融模块（Financial Module）**的设计，这是物流金融系统的价值核心。在您的业务逻辑中，金融模块主要负责将“仓单资产”和“物流位移”转化为“数字债权”，即记录并管理**应收款项（Account Receivables）** 。

---

### 1. 金融模块核心逻辑

#### 第一阶段：应收款生成（资产证券化）

系统通过物流动作自动捕捉贸易事实，将实物资产转化为账面债权：

* **新货入库场景** ：当货物通过物流进入监管仓并产生**新仓单**时，系统自动关联预设单价，生成一笔基于实物价值的“原始应收款”。
* **转让配送场景** ：在“转让配送”模式下，当买方点击**签收确认**后，系统判定贸易交付完成，自动将原本的仓单资产状态转化为一笔针对买方的“贸易应收款”。

> **通俗解释** ：货一到库或买家一签收，系统就自动在账本上记下：“某某欠某某多少钱”，物流单就是底账。

#### 第二阶段：金额动态调整（随物流变动）

由于实物在运输和存放过程中是动态的，应收款金额必须实时联动：

* **部分提取与拆分** ：当一份大仓单被拆分为多份，或仅提取其中一部分货物时，系统会自动按比例**切分**应收款。
* **物流损耗处理** ：当“送达数量”小于“起运数量”时（如矿产、液体货物的合理损耗），系统会根据仓库反馈的实收数据，自动**调减**应收款总额。

> **通俗解释** ：拉走一半货，账就拆成两半；路上撒了一点货，账就自动减掉那一点钱。

#### 第三阶段：还款与核销（闭环清算）

* **分批偿还** ：允许客户“有多少还多少”。每还一笔钱，系统自动更新剩余欠款，并按还款比例“释放”对应价值的货物。
* **以物抵债（仓单冲抵）** ：如果客户没钱，可以直接申请将手中的**仓单所有权**转让给债权人。系统自动计算货值并冲销债务。

### 2.操作权限矩阵

为了保证金融数据的安全，我们结合了 **角色（RBAC）**和**属性约束（ABAC）** ：

* **RBAC** 决定“谁能看、谁能点”。
* **ABAC** 决定“在什么条件下（如必须是债权人、必须未结清）才能点”。

| **业务动作**      | **操作角色**    | **权限范围 (RBAC)** | **触发/限制条件 (ABAC)**                       |
| ----------------------- | --------------------- | ------------------------- | ---------------------------------------------------- |
| **生成应收款**    | **系统/货主**   | 资产入库/签收权限         | 必须有关联的物流单且状态为“已送达”。               |
| **金额修正/调账** | **货主/仓库**   | 调账操作权限              | 仅限“状态=生效中”且“损耗数据”已上传时。          |
| **分批还款登记**  | **债务人/买方** | 还款操作权限              | 还款金额**$\le$**待还余额。                        |
| **以物抵债申请**  | **债务人/买方** | 资产处置权限              | 抵债仓单的 `owner_id`必须为当前操作企业。          |
| **抵债确认/过户** | **债权人/卖方** | 债权确权权限              | 确认后系统自动触发仓单 `owner_id`变更逻辑。        |
| **查询/对账**     | **三方主体**    | 财务查看权限              | 仅能查看与自身企业 ID 相关的账单数据。               |
| **风控预警设置**  | **银行/资方**   | 金融风控权限              | 当 `balance_unpaid`超过 `due_date`未结清时报警。 |

### 3.电子应收款项表

| **字段名**                | **类型** | **约束**         | **说明**                                                          |
| ------------------------------- | -------------- | ---------------------- | ----------------------------------------------------------------------- |
| **`id`**                | `Long`       | `PK`, 雪花算法       | 账款记录唯一主键 ID。                                                   |
| **`receivable_no`**     | `String`     | `Unique`,`NotNull` | **账单编号** ：业务展示单号（如 AR20260220001）。                 |
| **`business_scene`**    | `Integer`    | `NotNull`            | **来源场景** ：1-入库生成；2-转让配送签收生成。                   |
| **`source_voucher_id`** | `Long`       | `Indexed`            | **关联物流单** ：追溯产生这笔账的具体物流任务。                   |
| **`creditor_ent_id`**   | `Long`       | `NotNull`            | **债权人 ID** ：应收方企业（卖方/原货主）。                       |
| **`debtor_ent_id`**     | `Long`       | `NotNull`            | **债务人 ID** ：应付方企业（买方/借款企业）。                     |
| **`initial_amount`**    | `Decimal`    | `NotNull`            | **原始金额** ：基于初始发货/入库数量计算的金额。                  |
| **`adjusted_amount`**   | `Decimal`    | `NotNull`            | **结算金额** ：扣除物流损耗、拆分后的 **应收总额** 。       |
| **`collected_amount`**  | `Decimal`    | `Default: 0`         | **已回收金额** ：累计所有分批还款（现金+抵债）的总额。            |
| **`balance_unpaid`**    | `Decimal`    | `NotNull`            | **待还余额** ：结算金额 - 已回收金额。                            |
| **`currency`**          | `String`     | `Default: 'CNY'`     | **币种** 。                                                       |
| **`due_date`**          | `DateTime`   | `NotNull`            | **最后还款日** ：逾期判定的基准时间。                             |
| **`status`**            | `Integer`    | `Default: 1`         | **账款状态** ：1-待确认；2-生效中；3-部分还款；4-已结清；5-逾期。 |
| **`is_financed`**       | `Boolean`    | `Default: false`     | **融资标识** ：该笔应收款是否已向银行申请融资。                   |
| **`parent_id`**         | `Long`       | `Nullable`           | **父级 ID** ：账款发生“拆分”时，指向原大额账单 ID。             |

### 4.金融模块 API 接口设计表

| **接口名称**     | **路径 (Method)**                | **主要入参**                                | **后台逻辑说明 (通俗易懂版)**                                                                                     |
| ---------------------- | -------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **应收款预生成** | `/finance/receivable/generate`(POST) | `voucher_id`,`unit_price`                     | **【物流联动】**当物流状态变为“已送达”时自动调用。系统计算：`初始金额 = 实际重量 × 单价`。状态设为“待确认”。     |
| **账单确权确认** | `/finance/receivable/confirm`(POST)  | `receivable_id`,`signature`                   | **【债权生效】**债务人（买方）对账单进行数字签名确认。确认后，账单正式生效，具备法律效力。                              |
| **金额动态修正** | `/finance/receivable/adjust`(PATCH)  | `receivable_id`,`adjust_type`,`amount`      | **【随货变动】**处理损耗或拆分。`adjust_type`包括：1-物流损耗扣减、2-仓单拆分同步。系统自动更新 `adjusted_amount`。 |
| **现金分批还款** | `/finance/repay/cash`(POST)          | `receivable_id`,`amount`,`payment_voucher`  | **【部分还款】**记录本次还款额，增加 `collected_amount`。若设有“还款释放”规则，则自动解除对应比例货物的锁定。       |
| **仓单抵债核销** | `/finance/repay/offset`(POST)        | `receipt_id`,`offset_price`,`signatureHash` | **【以物抵债】**验证仓单所有权。确认后，仓单 `owner_id`变更为债权人，同时按抵债价值冲减账单余额。                     |
| **账务流水查询** | `/finance/receivable/flows`(GET)     | `receivable_id`                                 | **【财务对账】**获取该笔账单下所有的还款记录（现金流水或抵债记录），展示“还款进度条”。                                |
