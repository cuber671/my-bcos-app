本项目采用  **垂直分层架构 (Vertical Slice Architecture)** ，以业务模块为核心进行代码组织。这种设计确保了模块间的高内聚、低耦合，便于后期向微服务架构演进。

# 模块内部结构

以 `Enterprise`（企业模块）为例，每个独立业务模块均包含以下子包：

| **目录名称**         | **职能描述**     | **说明**                                                                                 |
| -------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------- |
| **`controller`**   | **控制层**       | 负责处理 HTTP 请求，进行参数校验，并分发业务至 Service 层。                                    |
| **`service`**      | **业务接口层**   | 定义业务逻辑的契约（Interface），屏蔽具体实现细节。                                            |
| **`service.impl`** | **业务实现层**   | 编写核心业务逻辑，包括对区块链 SDK 的调用和多表操作。                                          |
| **`mapper`**       | **持久层**       | MyBatis 接口文件，负责与数据库表进行交互。                                                     |
| **`entity`**       | **数据库实体**   | 与数据库表结构一一对应的 PO (Persistent Object)。                                              |
| **`dto`**          | **请求传输对象** | (Data Transfer Object) 接收前端传来的参数，支持复杂的参数校验。                                |
| **`vo`**           | **响应展示对象** | (Value Object) 返回给前端的展示数据，已过滤敏感字段（如私钥、密码）。                          |
| **`converter`**    | **对象转换器**   | 负责 DTO ↔ Entity ↔ VO 之间的相互转换，保持代码整洁。                                        |
| **`enums`**        | **业务枚举**     | 存放该模块特有的状态、类型枚举。**根据业务需求** ，仅当模块涉及状态机或分类时使用。）。 |
| **`handler`**      | **事件处理器**   | 处理异步回调、区块链事件监听 (Event Listener) 或特定的业务钩子。                               |
